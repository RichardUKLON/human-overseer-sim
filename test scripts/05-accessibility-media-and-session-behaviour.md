# 05 — Accessibility, media, and session behaviour

You are testing usability and resilience in **The Human Overseer** eLearning course.

## Goal

Confirm that learners can operate the course with keyboard navigation, read its feedback, play media, and recover from ordinary interruptions.

## Test procedure

1. Use keyboard only. Tab through buttons, flag text segments, choose decisions and reasoning, commit, open/close panels, play media, and reset.
2. Verify visible focus, sensible focus order, Enter/Space activation, arrow-key behaviour in radio choices, and no keyboard trap.
3. Check headings, labels, live updates for flag counts, button names, colour-dependent meaning, and screen-reader-facing descriptions where available.
4. Test at desktop width, narrow laptop width, tablet width, and mobile width. Record clipped text, hidden controls, horizontal scrolling, or overlapping panels.
5. Play every briefing and consequence format: embedded video, local video, voicemail transcript, email, and chat. Confirm controls and transcripts work.
6. Refresh during a briefing, review, consequence, and debrief. Record progress and note behaviour. The application states that progress is in memory unless SCORM supplies persistence.
7. Test an unavailable or slow media request. Confirm the learner receives a useful fallback rather than a broken or blank screen.
8. If the course runs in an LMS, test launch, suspend/resume, score reporting, completion, replay, and reset there as a separate environment.

## Report format

List each issue with device/browser context, reproduction steps, expected and actual behaviour, severity, and suggested remedy. State which checks you could not perform and why.
